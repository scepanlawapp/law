# Matter, Participants, and Proceedings

## Matter

A Matter is the law firm's internal workspace.

Conceptual fields:

```text
id
firm_id
internal_number
title
state
practice_area_id
stage_id
priority
responsible_user_id
description
opened_at
closed_at
created_at
created_by
updated_at
updated_by
archived_at
```

## Internal number

`internal_number` is generated by the backend.

Example:

```text
2026-00127
```

It is not the court/proceeding number.

Use an appropriate unique constraint within the tenant, for example:

```text
unique(firm_id, internal_number)
```

The exact numbering format may be repository/product specific. Do not invent or change the format without checking existing requirements.

## Matter lifecycle state

System enum:

```text
DRAFT
OPEN
CLOSED
```

Archiving is separate from lifecycle state and can be represented with `archived_at` or the repository's established archive mechanism.

## Priority

System enum:

```text
LOW
NORMAL
HIGH
URGENT
```

Default:

```text
NORMAL
```

## Practice area

`practice_area_id` references a firm-configurable lookup.

Do not implement a large hard-coded case-type enum.

## Stage

Matter stage is a business workflow stage, not the lifecycle state.

It is firm-configurable and may optionally be scoped to a PracticeArea.

Examples for litigation:

- Preparation;
- Claim filed;
- Response;
- Evidence;
- Awaiting judgment;
- Appeal.

Examples for contract work:

- Information gathering;
- Draft;
- Internal review;
- Client review;
- Negotiation;
- Signature.

## Matter clients

A Matter may have multiple Clients.

Use a relationship such as:

```text
MatterClient
id
matter_id
client_id
is_primary
notes
created_at
```

Do not use a single `matter.client_id`.

Recommended uniqueness:

```text
unique(matter_id, client_id)
```

At most one Client should be primary for a Matter if the product uses a primary Client.

## Creation requirements

Backend draft creation must be able to create a DRAFT Matter with at least:

- title.

Normal UI "Open matter" flow requires:

- title;
- at least one Client.

The backend should enforce the rule when transitioning/opening, not only in the browser.

## Participants

Do not create a special `OppositeParty` identity model.

Use a generic `MatterParticipant`:

```text
id
matter_id
party_id
notes
```

Roles are separate so a participant can have multiple roles:

```text
MatterParticipantRole
id
matter_participant_id
participant_role_id
```

ParticipantRole is firm-configurable.

Seed examples may include:

- Plaintiff;
- Defendant;
- Applicant;
- Respondent;
- Injured party;
- Accused;
- Witness;
- Expert;
- Legal representative;
- Attorney/representative;
- Opposing party;
- Other.

Labels can be localized.

## Proceeding

Do not put the only court number, court, and judge directly on Matter as if a Matter can have only one proceeding.

Conceptual Proceeding:

```text
id
matter_id
type_id
external_number
authority_id          nullable
authority_name        nullable transitional/V1
judge_name            nullable transitional/V1
status                nullable
started_at
ended_at
notes
created_at
updated_at
```

A V1 may use text for authority/judge when no institution directory exists yet.

A Matter can have:

```text
Matter: Damages — Petrović v Delta

Proceedings:
P 1234/26 — first instance
Gž 532/27 — appeal
I 942/28 — enforcement
```

ProceedingType should be a configurable lookup.

## Matter create UI

Suggested V1:

```text
Title *
Clients *
Practice area
Stage
Priority
Responsible lawyer
Opened date
Description

Participants
+ Add participant

Proceedings
+ Add proceeding

[Save draft] [Open matter]
```

Controls:

- Title: text input;
- Clients: multi autocomplete;
- Practice area: searchable select + inline create;
- Stage: searchable select + inline create;
- Priority: select or compact segmented control consistent with design system;
- Responsible user: autocomplete;
- Opened date: date picker;
- Description: textarea.

Client autocomplete should include:

```text
+ Create new client
```

A successful quick create should select the new Client.

## Matter detail V1

Header:

- internal number;
- title;
- state;
- practice area;
- priority;
- primary Client;
- responsible user;
- opened date.

Tabs:

```text
Overview
Documents
Participants
Proceedings
Activity
```

Future tabs may include Tasks, Calendar, Time, Expenses, Invoices, Email, and AI.

Overview should summarize important information rather than reproduce an edit form.
